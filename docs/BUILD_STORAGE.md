# 构建、验证和备份空间管理

日期：2026-10-25

## 边界

企业版与个人版独立执行本规则。企业版使用既有本地构建根，个人版只使用用户主目录下登记的 `.cilai-personal-builds/desktop`，源码位置通过显式登记关联，拒绝云同步根和路径联接。源码、运行数据、凭据、工具链及缓存不跨版本联接。不修改系统进程、交换文件或 Time Machine；不以目录账面减少代替磁盘实际释放量。

正在运行的应用仍由既有打包进程检查保护：未正常退出不能覆盖，不创建第三个输出目录绕过限制。构建测试不自动结束当前应用。

## 构建和验证入口

- 常规打包继续使用 `npm run package`，质量检查继续使用平台的 `script/quality` 入口。
- 根 `npm run build`、`npm test` 和公开的产物型专项验证自动取得构建锁，暂存到固定构建根；已持有冻结清单时复用本轮，不重复暂存或创建临时目录。
- 自定义专项验证使用 `npm run verify:managed -- <命令及参数>`，默认工作目录为固定构建根。外部脚本、输入和报告必须使用绝对路径；工具不猜测自定义参数的路径含义。
- `npm run verify:build-reuse` 暂存一次源码，校验相同清单，连续执行两次打包前准备，并记录每次耗时和空间。它包含前端编译、Rust 服务、平台组件及随包暂存，不包含依赖安装、Electron 最终组包、签名、启动自检或发布。此入口可以在当前应用保持运行时使用。
- `npm run verify:package-reuse` 在同一把构建锁内暂存一次源码，连续执行两次标准依赖处理、完整打包和启动自检；不启动常驻应用。报告单独写入 `target/storage-reports/verify-package-reuse.json`。正在使用的成品包不能覆盖；源码清单改变或第一遍失败时停止后续遍次。完整打包计时与准备阶段计时分别报告。
- `npm run test:storage` 校验空间管理、备份保留和验证脚本生命周期，使用小型隔离夹具。

正常启动常驻应用前恢复构建前的临时环境并移除构建锁身份，避免应用后续使用已回收目录。

锁的最外层创建 `tmp/storage-runs/<本轮编号>`，把临时环境变量交给该目录。小型结果报告位于 `target/storage-reports`。子命令退出、源码清单核验通过、报告写盘并确认目录无进程占用后，才删除本轮临时目录。失败和仍被占用的目录保留；异常中断沿用原构建锁的人工核实规则。只处理本工具登记的目录，不扫描删除旧 `/tmp`、工作区、来源快照或业务数据。

macOS 使用打开文件检查确认空闲。Windows 暂无完整的打开句柄检查，自动清理明确记为待检查并保留本轮目录；未经 Windows 实机验证的行为不能引用 macOS 结果作为验收。Windows 工具链仍遵循现有英文临时目录寻址约定。

macOS 的 Swift 编译通过唯一英文路径别名访问本轮受管临时目录，规避当前编译器处理中文临时路径时的崩溃。别名不形成新的构建输出根；退出时只删除归属核验通过的链接与登记文件，实际临时数据仍按本轮成功或失败状态处理。

保留 Cargo 的依赖、build、fingerprint、正常 profile 缓存、下载缓存、node_modules、Electron、Swift 和各平台工具链。质量检查不删除 Release 缓存。常规编译固定 `target`；确有上游专用工具链需求的原生扩展套件使用固定 `target/codex-harness`，关闭增量对象。不得为任务编号再创建 `target-t4-*`、`target-r5-*` 等目录；临时夹具、运行目录和重复 sidecar 不是编译缓存。

个人版在锁文件、依赖清单、Node 版本及平台未变，且本地依赖归档内容及安装清单校验通过时复用已安装依赖；输入或安装内容不符时重新执行锁定安装。缓存登记仅在安装成功后更新。依赖安装和编译缓存不共用企业版目录。

## 完整备份

备份由 `npm run storage:backup -- create|verify|prune` 管理；参数见 `--help`。每个版本、每个数据集独立登记源目录和专用备份根。备份根必须在源目录之外，不能把历史备份再次装入新备份。

创建方必须先取得源数据真正的独占写保护，例如应用正常退出且阻止再次打开、或数据所有者提供的写入暂停协议，然后提供工具要求的保护凭证。普通构建锁不能证明运行中数据库已经停止写入；不要伪造保护文件。本工具检查凭证与存活持有者，并在复制前后对源和副本逐项核验文件大小、SHA-256、目录和符号链接。它不负责停止应用或系统进程。完整性范围为文件内容、权限、目录和内部链接；此工具不保存 macOS 扩展属性、ACL 或文件所有者，依赖这些属性的数据不能据此宣称系统级完整恢复已验证。

只有完整校验通过的备份才参与保留排序。新备份完成后，同一数据集保留最近两份已验证完整备份；删除更旧副本前重新完整校验保留点。未登记的历史备份、失败备份、固定保留或待恢复的副本不自动删除。只有一份时不会删除它，也不会把未验证副本凑成第二份。保护标记会使总保留数超过两份，这是有意保留恢复依据。

既有业务备份不会因为新增规则就自动登记或清理，也不对运行中的应用现场创建冷备份。未来涉及会改变业务数据的验收，须先按数据集完成本流程，再继续操作。

专项验收顺序为：数据所有者取得真正写入排他保护，使用备份工具创建并校验该数据集备份，再通过受管验证入口运行验收。备份根和数据集须显式指定，保护凭证的来源和生命周期由数据所有者负责。应用内数据库迁移、历史恢复及用户主动导出的备份保持原有业务规则，不能套用构建临时目录回收或据此宣称已纳入两份保留。以前保存在测试证据和临时目录中的一次性脚本不自动改写；重跑前必须遵循本流程。

## 空间观察

每轮记录文件系统可用字节和本轮临时数据。完整目录逻辑占用在每日首次或自上次完整采样以来卷可用空间下降至少 20 GB时刷新，复用采样必须注明时间，不据此声称本轮目录增长为零；重复构建验收单独完整扫描，并另列 POSIX 文件分配字节。APFS 克隆、快照和其他进程活动会影响解释，不能把各个包含关系目录相加。

个人版既有 `target-runtime-audit` 纳入完整统计，其中 `fixtures` 超过 20 GB 单独提醒。该目录混有运行时缓存和失败证据，既有成功夹具自行清理，失败证据及未登记内容保留；本工具不会整目录删除。

登记临时数据超过 20 GB、最近完整采样发现当日构建目录增长超过 20 GB或可用空间低于 100 GB时输出提醒和报告位置。提醒不会触发缓存、用户数据或系统内容删除。应检查失败验证、未结束子进程和新增缓存组，并按登记记录处理。

## 本地构建根与历史资料

个人版构建根位于用户主目录的 `.cilai-personal-builds/desktop`，拒绝云同步根和链接祖先。迁移只移动无占用的标准缓存及依赖，逐项记录 inode 和归属；iCloud 正在读取的旧验收资料原位保留，旧根设置退役标记，不再作为构建入口。旧空间报告按原内容归档，不批量重写历史路径。仅对指定生成目录内逐项内容一致的副本进行清理，未知和不同内容资料保留。

纯只读核对保留原路径语义；内部测试串、workspace 及直接 Cargo 命令属于底层入口。日常使用根构建、根测试、平台质量检查及公开验证命令。验证夹具在初始化失败时同样关闭自己的服务并保存诊断；成功且无占用后才回收。Windows 无法完整确认句柄占用时明确保留待检查，不将 macOS 结果作为 Windows 实机结论。
